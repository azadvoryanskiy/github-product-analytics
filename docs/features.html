Feature usage · retention

Which features keep people on the platform?

Almost none of them on their own. Every feature looks like it helps until you compare people who were active the same number of days — then most of the gaps collapse, and two of them turn negative. What survives is how many features someone uses, not which.

How to read this

  1. Everyone active on GitHub between …, followed for 30, 60 and 90 days. Automation removed.
  2. Turn on "compare at equal activity" — that is the whole point of the page. Code review goes from +39 points to +12.8; pushing code goes from +11.5 to −2.7.
  3. Click any feature to follow it across every chart. Every number is in the table at the bottom, and it downloads as CSV.

What I would change

  • Stop asking which feature to push. Once activity is held constant, no single feature is worth more than about thirteen points, and two of the widest ones — pushing code and creating repositories — go negative. They are what everybody does, so using them says nothing.
  • Aim at the second and third feature instead. Accounts using one feature retain at 19.5%; at five, 67.5%. Breadth is the relationship that survives every cut on this page.
  • Code review is the one worth a real try. +12.8 points matched, the largest of any single feature, and only 3.4% of accounts touch it — the widest gap between value and reach.

How I would test it: take accounts that have used exactly one feature for a month and prompt the second — a review request, a first issue, a release. Outcome is 90-day retention against a held-out control. The matched gaps here are correlational and set the ceiling, not the expectation.
